# NAB Dataset Audit Findings

## Scope and source

This report summarizes the inventory generated by `scripts/audit_nab.py` from
the repository's `data/` CSV files and `labels/combined_windows.json`. The
recorded results are from the audit run performed on 2026-10-26. The generated
per-file report is `outputs/nab_dataset_inventory.csv`.

The audit is a data-integrity inventory, not a detector evaluation. It does not
modify NAB source data.

## Methodology and commands

The script recursively discovers CSV files under `data/` and reads the
combined anomaly-window JSON. It checks the required `timestamp` and `value`
columns, parses timestamps to UTC, counts missing and invalid timestamps,
duplicate timestamps and backward steps, separates missing/invalid/non-finite
values, and reports a median-cadence-based potential-gap count. It validates
label window structure and timestamp bounds, counts data rows in the union of
valid anomaly windows with inclusive endpoints, and reconciles data paths
against label paths after normalizing separators and redundant path components.
Unexpected per-file errors are recorded for that file so other files can still
be audited.

Commands run:

```powershell
python -m pytest tests\test_audit_nab.py tests\unit\audit_nab_test.py -q
python scripts\audit_nab.py
```

Three targeted checks were also made directly against the CSV and label source
files; results are listed below. Test coverage for unusual inputs uses
temporary fixture files and does not edit the NAB corpus.

## Dataset inventory

- **58 CSV files** audited, with **58 corresponding label entries**.
- **365,558 data rows** across the audited CSVs.
- **116 anomaly windows** declared: 116 valid, 0 invalid.
- **33,495 data rows** fall within the union of valid anomaly windows, using
  inclusive start and end boundaries.
- Audit status: 33 files `ok`; 25 files `data_quality_issues`.
- No label-only paths or data files without label entries were found.

The 25 files with data-quality status reflect duplicate timestamps,
out-of-order records, and/or potential time-gap warnings. These statuses do
not by themselves mean the data are unusable; see the distinction between
confirmed findings and heuristic warnings below.

## Data-quality issues and label discrepancies

### Confirmed findings

- **Duplicate timestamps:** 49 repeated timestamp occurrences across 8 files.
  The count is repeated rows after each timestamp's first occurrence, not the
  number of unique timestamp values affected. This confirms repeated timestamp
  records; it does not establish whether they are erroneous for the source
  metric.
- **Out-of-order timestamps:** 1 backward step in 1 file:
  `realKnownCause/machine_temperature_system_failure.csv`.
- **Missing or invalid timestamps:** none reported.
- **Missing, invalid-numeric, or non-finite values:** none reported.
- **Empty series, missing required columns, CSV read errors, and unexpected
  per-file audit errors:** none reported.
- **Label discrepancies:** no missing label entries, orphaned label paths,
  normalized-path collisions, malformed windows, or windows outside the
  timestamp range were found.

### Heuristic warnings (not confirmed missing data)

- **Potential time gaps:** 4,492 intervals across 24 files exceeded 1.5 times
  the file's median positive interval between distinct timestamps. This is a
  cadence heuristic. It does not infer how many samples are missing and can
  flag naturally irregular or irregularly sampled series.
- The largest warning counts were in `realTraffic/TravelTime_387.csv` (821)
  and `realTraffic/TravelTime_451.csv` (735). These counts should be reviewed
  against the source sampling behavior before being treated as data defects.

## Known limitations and unresolved issues

- A repeated timestamp is reported as a confirmed repeated record, but this
  audit cannot determine whether the duplicate is legitimate source behavior
  or a data defect. It does not deduplicate or alter source files.
- Potential-gap warnings depend on the median cadence and a fixed 1.5
  multiplier. They are not evidence by themselves that observations were
  lost. Irregular schedules, aggregation, or valid sampling changes can
  produce these warnings.
- Timezone-bearing timestamps are converted to UTC. Timestamps with no
  timezone are interpreted as UTC by the parser; the audit does not infer the
  original local timezone.
- The audit validates anomaly-window syntax, ordering, and coverage of the
  data time range. It does not independently establish whether labels are
  semantically correct for the underlying signal.
- The audit expects the combined label JSON to be readable and to contain a
  JSON object. A missing or malformed label document is a corpus-level setup
  error rather than a per-file data error.

## Recommended next steps

1. Ask the data owner whether the confirmed repeated timestamp records and the
   single out-of-order step are expected; retain the original rows unless a
   documented correction is approved.
2. Review the flagged traffic-series intervals against source collection
   cadence before classifying them as missing observations.
3. Preserve the generated inventory and rerun the documented tests and audit
   whenever data or labels change.
4. Treat any changes to labels, timestamps, or values as a separate,
   reviewable data-maintenance task; this audit makes no such changes.
